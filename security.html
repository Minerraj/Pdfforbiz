Security

PDFforBiz's privacy claim isn't just marketing copy — here's the actual technical explanation of how your files are handled.

Client-side processing, not a server

Every tool on this site — merging, compressing, converting, watermarking, redacting, and the rest — runs using JavaScript libraries (like pdf-lib and pdf.js) that execute directly in your browser. When you select a file, it's read into your browser's memory, processed there, and the result is offered back to you as a download. At no point is the file transmitted to a server for processing.

What this means in practice

  • Opening your browser's developer tools and watching the Network tab while using any tool will show no upload of your file content.
  • Closing the tab discards everything — there's no server-side copy left behind because none was ever made.
  • This is different from most online PDF tools, which typically upload your file to a server, process it there, and send back a result — a reasonable approach for most use cases, but one that involves your document leaving your device.

What does reach a server

The page itself (HTML, CSS, JavaScript, fonts) is loaded from Cloudflare's servers, same as any website. Anonymized traffic analytics (which pages are visited, roughly how many visitors) may be collected — see our Privacy Policy for details. None of this includes the content of files you process.

The Redact tool specifically

Because redaction has real consequences if done incorrectly, it's worth calling out directly: this tool works by flattening each page into a rasterized image after you draw over sensitive content, which permanently removes the underlying text layer from the output file. That said, always review the exported file yourself before sharing it — no tool should be trusted blindly with sensitive information.

Reporting a concern
